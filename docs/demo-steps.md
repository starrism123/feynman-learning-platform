# 验收演示：照着点的操作手册（2026-11-20 下午）

验收分两段：

1. **演示功能**：把每个模块点一遍，讲清楚这里是干什么的、用了什么。按下面第一、二节走，约 8 分钟。
2. **问 AI 再回答**：现场问 Claude，它会提固定的 5 个问题，我照着准备好的答案讲给老师。见第三节。

每一步分三行：

- **点**：要操作什么，加粗的是页面上按钮或链接的原文。
- **说**：参考说法，换成自己的话讲，不用背。
- **用了**：顺带提一句的技术名词。

## 二、演示步骤

### 第 1 步　开场（30 秒）｜停在登录页

**说**：

> 这是我做的「费曼学习平台」。费曼学习法就是把一个概念用自己的话讲给外行听，讲不清的地方就是没懂。平台做的是：写知识点笔记 → 开口复述 → AI 转文字、打分、出题；笔记还会建成我自己的知识库，可以提问，也能画成 2D 图谱和 3D 宇宙。
>
> 前端是 React，后端是 Node.js + Express，数据库是 MongoDB。还有一个本机跑的 Python 服务，负责语音识别和文本向量化。大模型用 DeepSeek，本地 Ollama 做备用。

### 第 2 步　登录（30 秒）｜登录页

**点**：输入邮箱和密码 → **登录**。顺手指一下底部的**去注册**，说明有注册功能。

**说**：

> 注册时密码不存原文，用 bcrypt 加盐哈希后再存。登录成功后服务器发一个 JWT，相当于一张签了名的通行证。之后前端每个请求都在请求头里带上它，后端验签名就知道是谁。

**用了**：bcrypt、JWT、Express 认证中间件。

### 第 3 步　我的知识点（30 秒）｜首页

**点**：

1. 指一下知识点卡片右上角的状态标签：**未开始 / 学习中 / 已掌握**。
2. 在**搜索标题或内容…**框里输入「JWT」，列表只剩一张卡。
3. 把搜索框清空。

**说**：

> 首页列出我的全部知识点，每张卡片都能直接开始复述、测评、编辑、删除。每个用户只能看到自己的知识点，后端查询时都按当前登录用户过滤。

**用了**：React 组件、React Router、axios（请求时自动带上 token）。

### 第 4 步　知识点详情：Markdown 笔记（40 秒）

**点**：点卡片标题**JWT 登录认证**，进入详情页，往下滚。

**说**：

> 笔记用 Markdown 写。这一条里有表格、数学公式、时序图：公式用 KaTeX 渲染，图用 Mermaid 渲染。渲染时不执行笔记里的原始 HTML，防止有人在笔记里藏脚本做 XSS 攻击。

**用了**：react-markdown、remark-gfm、KaTeX、Mermaid。

### 第 5 步　★ 复述：录音 → 转文字 → AI 打分（2 分钟）

**点**：

1. 详情页右上角点 **开始复述**。
2. 点 **● 开始录音**，不看原文，用 15–20 秒讲 JWT 是什么，再点 **■ 停止录音**。
3. 等约 4 秒，「语音识别结果」框里出现文字。有错字可以直接在框里改。
4. 点 **请 AI 教练点评**，按钮变成「AI 教练正在批阅…」，等约 5 秒。
5. 依次指：**AI 润色后的文本**、**综合评价**、**优点 / 待改进**、右侧的**综合得分**和四个维度（准确、清晰、完整、简洁）。

**说**：

> 录音用的是浏览器自带的 MediaRecorder，录完把音频上传到后端。语音识别没用讲义里的百度接口，换成了在本机跑的 Whisper 模型：不用申请密钥、不按次收费、断网也能用。
>
> 转出来的文字交给大模型，按四个维度打分，同时给出润色后的版本和改进建议。低于 60 分会自动加入复习列表，首页卡片上会出现「待复习」标记。

**用了**：MediaRecorder、FormData 上传、multer、Python Flask + Whisper、DeepSeek、要求模型按固定格式返回 JSON 的提示词。

> 麦克风出问题时：不用慌，直接在「语音识别结果」位置说明情况，跳过录音。也可以回到详情页，往下看「复述记录」里之前存下的结果。

### 第 6 步　★ 测评：AI 出题、判分（1 分钟）

**点**：

1. 点右侧的 **去做几道题巩固**（或回详情页点 **开始测评**）。
2. 题型点 **单选题**，难度点 **基础**，AI 现场出一道题（约 5 秒）。
3. 选一个选项 → **提交答案**，页面显示「回答正确 / 回答错误」和解析。
4. （时间够再做）题型点 **简答题**，输入一句话作答并提交，AI 给分数和答案要点。

**说**：

> 题目是 AI 根据这条笔记现场出的，题型和难度可以选。单选题直接比对答案，简答题由 AI 判分并给出答案要点。

**用了**：DeepSeek、结构化提示词（题干、选项、答案、解析都按固定字段返回）。

### 第 7 步　新建、编辑、删除（1 分钟，老师想看增删改时再做）

**点**：

1. 顶部导航点 **新建**。标题填「演示用知识点」，学习状态选「学习中」，内容写一两句，点 **创建**，自动跳到它的详情页。
2. 点 **编辑**，改一句话，点 **更新**。
3. 点顶部 **我的知识点** 回到首页，在这张卡片上点 **删除**，弹出「你确定要删除这个知识点吗？」后点「确定」。

**说**：

> 这是知识点的增删改查。后端接口按 REST 风格设计：新建用 POST，修改用 PATCH，删除用 DELETE，查询用 GET。保存知识点时，后台还会自动把它切成小段、转成向量，存进知识库，后面的 AI 助手就能检索到它。

**用了**：RESTful API、Mongoose Schema 校验、Markdown 编辑器。

### 第 8 步　★ AI 助手：知识库问答（2 分钟）

**点**：

1. 顶部导航点 **AI 助手**。指一下顶部那行：「知识库：8 个知识点 · 15 块」「向量服务在线」。
2. 点推荐问题 **为什么密码要加盐？**。回答是一段一段流出来的，句末有 [1][2]。
3. 点开下面的 **引用来源**，每条都显示来自哪个知识点、相关度多少，还有**打开这个知识点**链接。
4. 在输入框输入「红烧肉怎么做」，点 **发送**。它会直接说知识库里没有相关内容。

**说**：

> 这是 RAG，检索增强生成。每条笔记先切成小段，每段用本机的中文向量模型转成 768 维向量，存进 MongoDB。提问时把问题也转成向量，找出意思最接近的几段，再交给大模型，要求它只根据这些内容回答，并标出处。
>
> 所以回答可以核对来源。第二个问题和我的笔记无关，检索不到就直接拒答，根本不调用大模型，也就不会瞎编。回答用的是流式输出，大模型生成一点前端就显示一点。

**用了**：文本切分、bge-base-zh-v1.5 向量模型、余弦相似度检索、相关度门槛 0.3、SSE 流式输出。

### 第 9 步　知识图谱（1 分钟）

**点**：

1. 顶部导航点 **知识图谱**，等节点散开、停稳。
2. 用滚轮缩放，拖动一个节点。
3. 鼠标停在一条蓝色虚线上，看相似度。
4. 点一个节点，跳到对应知识点的详情页。

**说**：

> 这是用 ECharts 力导向布局画的知识图谱。黑色实线箭头表示一条笔记正文里提到了另一条的标题；蓝色虚线表示两条笔记内容相似，是用 AI 助手那套向量算出来的：两条笔记互相排进对方最相似的前 2 名，才连一条线，线越粗越相似。

**用了**：ECharts 力导向图、后端图谱接口算两种连线。

### 第 10 步　★ 3D 视界（1 分钟）

**点**：

1. 顶部导航点 **3D 视界**。
2. 先点右上角 **入门：旋转立方体**，展示最基础的 3D 场景。
3. 再点 **随机星图**：左键拖动旋转，滚轮缩放，右键拖动平移；鼠标移到一个星球上，它和相连的航线会高亮。

**说**：

> 3D 部分用的是 Three.js。最基础的三样东西是场景、相机、渲染器，旋转立方体就是这三样，再加一个每帧转一点的动画循环。
>
> 星图里每个星球是一个知识点。鼠标悬停高亮用的是射线拾取：从相机穿过鼠标位置发出一条射线，看它先碰到哪个星球。这一页的位置是随机的。

**用了**：Three.js（场景、透视相机、WebGL 渲染器、OrbitControls、Raycaster）。

### 第 11 步　★ 知识宇宙（1 分钟）

**点**：

1. 顶部导航点 **知识宇宙**，拖动旋转，看整体。
2. 点一个星球选中它，相邻的星球和连线会高亮，再点 **打开这个知识点** 跳到详情页（或点空白处取消选中）。

**说**：

> 和上一页不同，这里星球的位置是算出来的，用的是 d3-force-3d 力导向算法：有连线的知识点互相吸引，没关系的互相排斥，所以相关的知识会自然聚成一团。我还加了一个指向中心的弱引力，不然孤立的知识点会被推出画面。连线数据和 2D 图谱是同一份。

**用了**：d3-force-3d、Three.js，和 3D 视界共用一份场景代码。

### 第 12 步　跨平台（30 秒，只讲不点）

**说**：

> 同一份前端代码还做了两种形态：用 Electron 打包成 Windows 桌面安装程序；网页版加了 PWA，可以在 Chrome 里「安装」，断网后页面还能打开。部署这一课讲了 Docker 和上云服务器的流程，写在部署文档里，没有真正上线。

**用了**：Electron、electron-builder、vite-plugin-pwa（Manifest + Service Worker）、Docker。

> 不要现场打开 `release/` 里的桌面安装包：那是 10-29 打的，知识图谱页有个已修好的旧 bug。

**说**：

## 三、问 AI 环节：固定的 5 个问题

现场对 Claude 说：「**针对我的费曼学习平台，向我提 5 个问题**」。它会按下面的顺序提这 5 个问题，然后我转身讲给老师听。

答案是讲稿要点，每题讲 1 分钟左右。「被追问时」一行用来应对老师接着问。

### 问题 1：你的项目整体架构是怎样的？从前端点一个按钮到数据库，中间经过哪些环节？

> 项目分四块：React 前端、Node.js + Express 后端、MongoDB 数据库，再加一个本机的 Python AI 服务。
>
> 比如在首页点开一个知识点：前端用 axios 发请求，请求拦截器会自动在请求头里加上 JWT。后端收到后，先经过认证中间件验 token，确认是谁；再交给路由和控制器，控制器通过 Mongoose 模型按「当前用户 + 知识点 id」查数据库；结果以 JSON 返回，前端拿到后用 React 渲染出来。
>
> 后端按路由、控制器、服务、模型分层：路由只管路径，控制器处理请求，服务放业务逻辑（比如调大模型、向量检索），模型定义数据结构。分层之后改一层不影响别的层，也方便写测试。

**被追问时**：前后端端口不同（5173 和 3000）属于跨域，浏览器默认不让读响应，所以后端配了 CORS，声明允许前端的地址访问。

### 问题 2：登录认证是怎么实现的？怎么保证用户 A 看不到用户 B 的知识点？

> 注册时，密码用 bcrypt 加盐哈希后再存库。哈希是单向的，数据库泄露也反推不出密码；加盐让相同的密码存出来也不一样，防彩虹表。
>
> 登录时，用 bcrypt 比对密码，通过后签发 JWT。JWT 分三段：头部、载荷、签名。载荷里放用户 id，签名用只有服务器知道的密钥算出来，别人一改内容签名就对不上。
>
> 前端把 token 存在 localStorage，每次请求放在 `Authorization: Bearer` 请求头里。后端认证中间件验签名，把用户 id 挂到请求上。所有知识点查询都带上这个用户 id 作条件，所以 A 拿着 B 的知识点 id 也查不到，返回 404。

**被追问时**：载荷只是 Base64 编码，不是加密，谁都能解码，所以不能放密码。前端的路由守卫只管体验（没登录跳登录页），真正的安全靠后端中间件。

### 问题 3：AI 助手的知识库问答是怎么工作的？为什么它不会瞎编？

> 这叫 RAG，检索增强生成，分两步。
>
> 建库：每次保存笔记，后台按标题把它切成约 300 字的小段，相邻两段重叠 50 字，避免一句话被切断。每段用本机的 bge 中文向量模型转成 768 个数字组成的向量，存进 MongoDB。意思相近的文字，向量的方向也相近。
>
> 问答：提问时把问题也转成向量，和所有小段算余弦相似度，取最相近的 4 段，低于 0.3 的丢掉。把这几段和问题一起交给大模型，提示词要求它「只根据这些资料回答，每句标出处，资料里没有就说没有」。
>
> 不瞎编有两层保障：一是检索不到相关内容时，后端直接回复「知识库里没有」，根本不调用大模型；二是回答里的每一句都标了来源，可以点开核对。

**被追问时**：向量模型一开始用 Ollama 里的，实测无关句子的相似度反而比相关句子高，我写了体检脚本对比，换成现在的模型后两者差距在 0.2 以上。门槛 0.3、每段多长、取几段，都是跑 28 道评测题定的。

### 问题 4：复述功能里，声音是怎么变成文字、又怎么变成分数的？为什么不用讲义里的百度接口？

> 第一步，录音：浏览器的 MediaRecorder 把麦克风的声音录成一段音频，用 FormData 上传给后端，后端用 multer 接收文件。
>
> 第二步，转文字：后端把音频转给本机的 Python 服务，服务里用 Whisper 模型识别出文字，返回给前端显示，识别错的字可以手动改。
>
> 第三步，打分：把文字和原笔记一起交给 DeepSeek，提示词规定它按准确、清晰、完整、简洁四个维度打分，并返回润色后的文本、优点、待改进，格式固定成 JSON，前端直接按字段展示。低于 60 分自动加入复习列表。
>
> 不用百度是因为：本地 Whisper 不用申请密钥、不按次收费、断网也能识别，录音也不用上传到第三方。代价是电脑要先下载模型、占一些内存。

**被追问时**：大模型统一走 OpenAI 兼容接口，DeepSeek 出错时自动换成本地 Ollama 的 qwen2.5:7b 模型，所以换模型只要改配置。

### 问题 5：知识宇宙里星球的位置是怎么决定的？3D 场景是怎么画出来的？

> 3D 用 Three.js 画，基本结构是三样东西：场景，放所有物体；相机，决定从哪个角度看；渲染器，把画面画到网页的 canvas 上。再用一个动画循环每秒重画约 60 次，配合 OrbitControls 实现拖动旋转和缩放。
>
> 星球的位置用 d3-force-3d 力导向算法算：把知识点当成互相排斥的带电小球，把连线当成弹簧，有连线的被拉近，反复迭代到平衡。这样内容相关的知识点会自然聚成一团。我还加了一个指向中心的弱引力，防止孤立的点被推出画面。
>
> 点击选中用的是射线拾取：从相机穿过鼠标位置发出一条射线，第一个碰到的星球就是选中的那个。连线有两种：正文里提到了对方的标题，或者两条笔记的向量很相似。

**被追问时**：React 开发模式下 useEffect 会执行两次。一开始没写清理，页面上叠了两层画布、显存一直涨；后来在组件卸载时停掉动画循环、释放几何体和材质、移除画布才解决。

## 四、现场出问题

| 现象                              | 处理                                                                        |
| --------------------------------- | --------------------------------------------------------------------------- |
| 点评、出题、问答一直转圈          | DeepSeek 网络慢，会自动换本地 Ollama（多等 10–20 秒）；还不行就说明原因跳过 |
| 录音后没有文字                    | 「2 AI 服务」窗口被关了，或麦克风没授权；说明情况，跳过录音这一步           |
| AI 助手显示「需要重建」或检索不到 | 点 **重建索引**                                                             |
| 页面突然跳回登录页                | 登录过期，重新登录                                                          |
| 知识图谱空白                      | 刷新一次页面                                                                |
