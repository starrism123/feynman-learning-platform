## 0. 开场（约 0:00–0:35）

**画面**：片头卡「费曼学习平台 · 《大前端与AI实战》期中项目」，下方一行技术栈：React · Express · MongoDB · Whisper · DeepSeek。随后切到网站首页。

**旁白**：

费曼学习法有一个朴素的标准：能用自己的话把一个概念讲清楚，才算真正学会。

这个项目，就是把这个过程做成一个网站。先写下知识点，再对着麦克风讲一遍，由 AI 转写、点评、打分，最后再出题考一考。

接下来大约十分钟，我会沿着一位用户的使用流程，演示第一到第九课完成的全部功能，并讲解其中几段关键代码。

## 1. 整体架构（约 0:35–1:45）

**画面**：架构图（architecture.png），讲到哪个部分就高亮哪个框。

**旁白**：

先看整体架构。系统分成四个部分。

最左边是用 React 和 Vite 搭建的单页应用，负责页面、路由和录音。

中间是 Node.js 的 Express 后端。所有请求都先经过它：它负责注册登录、知识点的增删改查，也负责调度两项 AI 能力。数据存放在 MongoDB 里，用 Mongoose 定义数据模型。

第三部分是语音识别。讲义原本使用百度的语音识别服务，这里换成了在本机运行的开源模型 Whisper，用 Python 的 Flask 包装成一个接口。这样不用申请密钥，不按次数收费，录音也不必上传到第三方。

第四部分是大模型。默认调用 DeepSeek；如果断网或者额度用完，会自动切换到本机用 Ollama 运行的通义千问七B 模型，保证演示随时能跑。

浏览器只和后端打交道，Whisper 和大模型都藏在后端后面。这样密钥只留在服务器上，以后要换模型，前端一行代码都不用改。

## 2. 注册与登录（约 1:45–3:00）

**画面**：注册页填写并提交 → 跳到登录页，顶部提示「注册成功」→ 登录 → 进入知识点列表。然后切到代码 1。

**代码 1**：左右分屏。左边 `feynman-platform-frontend/src/api/axios.js` 的请求拦截器和响应拦截器；右边 `src/middleware/auth.js` 的 `auth` 函数。

**旁白**：

现在从注册开始。填写用户名、邮箱和密码后提交，后端先校验格式，再用 bcrypt 把密码加盐哈希后存进数据库。数据库里从不保存明文密码。

登录成功后，后端签发一个 JWT 令牌。它像一张签了名的通行证，里面记着用户编号和过期时间。

来看这段代码。前端用 axios 的请求拦截器，在每次请求发出前，自动把令牌放进 Authorization 请求头。后端的认证中间件取出令牌，用服务器密钥验证签名；验证通过，就把用户信息挂到请求上，交给后面的业务代码。

如果令牌过期或者被篡改，后端统一返回 401。前端的响应拦截器收到后，会清掉登录状态，把用户带回登录页。

另外，所有知识点的查询都会带上当前用户的编号，每个人只能看到、修改自己的数据。

## 3. 知识点管理（约 3:00–4:10）

**画面**：知识点列表，在搜索框输入「React」过滤 → 清空 → 点「新建知识点」→ Markdown 编辑器左写右预览，依次出现表格、公式、流程图 → 保存 → 打开「JWT 登录认证」详情页。

**旁白**：

登录后进入知识点列表。每张卡片显示标题、学习状态和内容预览，上方可以按标题或内容搜索。

点击新建，打开 Markdown 编辑器，左边写，右边实时预览。除了标题和列表，这里还支持表格、用 KaTeX 渲染的数学公式，以及用 Mermaid 画的流程图和时序图，很适合记录技术类知识。

用户写的内容会被渲染成网页。为了防止有人在内容里藏恶意脚本，渲染前会先做一遍安全过滤。

保存后，知识点出现在列表里，状态分为未开始、学习中和已掌握三种。接下来，就拿这条「JWT 登录认证」，做一次费曼复述。

## 4. 录音复述与语音识别（约 4:10–5:45）

**画面**：复述页，点「开始录音」，红点闪烁、计时走动（这一段加速播放，同时能听到复述录音的前几秒）→ 停止 → 「正在上传并转录」→ 识别结果出现。切到代码 2，再切回识别结果，圈出错字。

**代码 2**：`feynman-platform-frontend/src/hooks/useAudioRecorder.js` 的 `start` 函数（`ondataavailable` 和 `onstop` 两段）；右下角小窗放 `whisper-service/app.py` 的 `model.transcribe(...)` 那一行。

**旁白**：

在复述页点击开始录音，浏览器会请求麦克风权限。这时候合上书，用自己的话把这个知识点讲一遍。

讲完点击停止。录音会自动上传到后端，几秒钟后，识别出的文字就出现在下面。

录音功能是自己写的一个 React Hook。讲义推荐的录音组件库只声明支持到 React 18，而本项目用的是 React 19，所以这里直接使用浏览器原生的 MediaRecorder：录音时，数据一小块一小块地到达，先存进一个数组；停止时，再把它们拼成一个完整的音频文件，用表单上传。

后端用 multer 接收文件，转发给 Whisper 服务。Whisper 这边指定了中文，并给了一句提示，让它倾向于输出简体字。

仔细看识别结果，会发现几个同音错字：「会话」被识别成了「汇化」，「载荷」被识别成了「载贺」。这是语音识别的常见问题，文字框可以手动修改，下一步的 AI 润色也会处理它。

## 5. AI 教练点评（约 5:45–7:35）

**画面**：时序图（feynman-sequence.png），按编号逐步高亮 → 回到复述页点「请 AI 教练点评」→ 结果区：润色文本（错字处高亮）、右侧综合分和四个维度、下方优点和缺点、底部「DeepSeek · 耗时」。然后代码 3、代码 4。

**代码 3**：`src/services/llmService.js` 的 `chatJson` 函数（for 循环和 catch 部分）。

**代码 4**：`src/services/prompts.js` 的 `feynmanEvaluationPrompt`，聚焦输出格式那几行和「同音错别字不算学生的错」那一句。

**旁白**：

点击「请 AI 教练点评」。先用这张时序图看一下数据是怎么流动的：浏览器把识别出的文字和知识点编号发给后端；后端从数据库取出知识点原文，和学生的复述一起拼成提示词，交给大模型；大模型返回 JSON 格式的结果，后端把这次复述存档，再根据分数更新知识点的状态。

结果出来了。最上面是润色后的文字，「汇化」和「载贺」都已经改回了「会话」和「载荷」。右边是综合分，这次是七十分，下面是准确性、清晰度、完整性、简洁性四个维度的得分。再往下，列出了讲对的地方和遗漏的地方，比如这次复述没有提到，签名是用来防止内容被篡改的。如果综合分低于六十分，这个知识点会自动加入复习列表。

调用大模型的代码集中在一个服务里。DeepSeek 和 Ollama 都兼容 OpenAI 的接口格式，所以只写一份调用逻辑，再按顺序尝试：前一个失败，就记下原因，换下一个；全部失败，才返回错误。页面上显示的模型名称和耗时，就是从这里返回的。

提示词的设计也踩过一个坑。最初的版本在输出格式里写了示例分数，结果本地的小模型直接照抄示例，每次都给出一样的分数。后来把示例改成了填写说明，并明确告诉模型：同音错字是语音识别造成的，不算学生的错。改完以后，分数才真正跟着复述的内容变化。

## 6. AI 出题与测评（约 7:35–8:50）

**画面**：点「测评」→ 选「单选题」「中等」→ 出现题目 → 故意选一个错误选项提交 → 正确项变绿、所选项变红，提示「已加入复习列表」→ 切「简答题」「基础」→ 输入答案 → 提交 → 显示得分、评判理由和答案要点。

**旁白**：

讲完之后，再用测评检验一下。在测评页选择题型和难度，AI 会根据知识点的内容现场出题。

先来一道中等难度的单选题。这里故意选一个错误的选项。提交后，正确答案显示为绿色，选错的显示为红色，这个知识点也被加入了复习列表。单选题的答案在出题时就已经确定，所以直接在前端判断对错。

再换一道基础难度的简答题。简答题没有唯一的标准答案，所以交给 AI 来阅卷：它对照出题时生成的答案要点，判断回答是否覆盖了关键内容，给出分数和理由。

大模型的输出并不总是可靠。所以后端会检查返回的题目是否完整，比如单选题必须有四个选项和一个合法的答案；不合格就返回错误，而不是把残缺的题目交给用户。
